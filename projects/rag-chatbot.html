FILE 01 — THE MISSION

RAG FOR TEAMS THAT CAN'T LEAK DATA

Some documents can never leave the building — compliance says so, clients say so, common sense says so. That rules out every RAG tutorial that starts with an external API key.

This chatbot runs the entire pipeline locally: Ollama for inference, ChromaDB for vectors, FastAPI in front. Data-privacy compliance isn't a feature flag — it's the architecture. And because production means accountability, every query, retrieval, and response lands in a structured audit log. The dossier writes itself.

"If you can't audit the answer, you can't ship the answer."

  • DOSSIER SNAPSHOT
  • Zero — external API calls
  • Local — Ollama inference, on your metal
  • ChromaDB — chunking, indexing, top-k retrieval
  • FastAPI — clean REST integration layer
  • Audited — every interaction on record
FILE 02 — THE PIPELINE

DOCUMENT IN, GROUNDED ANSWER OUT

01

Ingest & Chunk

Documents are parsed and chunked for retrieval — sized so answers cite focused context instead of entire files.

02

Embed

Chunks become vectors with local embedding models — nothing leaves the machine, not even for math.

03

Index

ChromaDB stores and indexes the vector space for fast similarity lookups across the corpus.

04

Retrieve

Semantic search pulls the top-k relevant chunks for each query — the needle, not the haystack.

05

Generate

Local Ollama inference answers grounded in the retrieved context — zero external dependency, full data custody.

06

Audit

A structured log records every query, retrieval set, and response — the whole interaction traceable end to end.
